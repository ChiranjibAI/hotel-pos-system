# Level 11: AI Features Bundle Implementation Plan

> **For Hermes:** Delegate to Claude Code in 5 batches. Build + `flutter analyze` + verify after each batch before starting the next. Use print mode (`claude -p`) with `--max-turns 30 --allowedTools Read,Write,Edit,Bash`.

**Goal:** Add 15 AI-powered features to Hotel POS System, making it the most intelligent restaurant POS in the SMB market.

**Architecture:** All features build on existing Sembast NoSQL DB + Repository+ChangeNotifier pattern + go_router navigation. AI features split into: (A) pure-Dart analytics using existing order/menu/inventory data, (B) LLM-backed features via http POST to configurable endpoint (Ollama/OpenAI-compatible, default localhost:11434), (C) on-device vision/OCR via image_picker + tflite_flutter or cloud fallback, (D) voice upgrades via speech_to_text. Each feature gets its own page + route + settings entry. No feature breaks existing functionality.

**Tech Stack:** Flutter 3.41+, Dart 3.11+, existing deps + new: `speech_to_text` (voice), `google_mlkit_text_recognition` (OCR), `tflite_flutter` (on-device vision, optional), `image` (already present). LLM features use existing `http` package — no new dep needed for those.

**Existing patterns to follow:**
- Repository: `class XRepository extends ChangeNotifier with Repository<T>, RepositoryStorage<T>` (see lib/models/repository/staff.dart)
- Service: singleton with `static instance = X();` (see lib/services/storage.dart, whatsapp_receipt_service.dart)
- Page: StatelessWidget/StatefulWidget with dark+gold theme, GoogleFonts.plusJakartaSans (see lib/ui/voice/voice_ordering_page.dart)
- Route: add GoRoute to lib/routes.dart, add import at top
- Settings entry: add to lib/ui/home/settings_page.dart in appropriate section
- Theme: `BrandColors.gold` (#FFD700), dark background, card-based UI

## Pitfalls

1. **ML Kit text recognition requires minSdk 21** — already set in flutter_launcher_icons config. Verify android/app/build.gradle minSdkVersion >= 21.
2. **speech_to_text requires microphone permission** — add to android/app/src/main/AndroidManifest.xml: `<uses-permission android:name="android.permission.RECORD_AUDIO"/>`
3. **image_picker requires camera permission** — add `<uses-permission android:name="android.permission.CAMERA"/>` if not already present. Check existing manifest first.
4. **LLM endpoint default to Ollama localhost** — on physical phone, localhost = phone, not dev machine. Document that owner needs to run Ollama on phone (Termux) or use cloud endpoint. Default to cloud-friendly config.
5. **No feature should crash if LLM unavailable** — every LLM feature must have a non-LLM fallback (keyword match, template, manual mode).
6. **Recipe costing data may not exist** — forecast and PO features must handle empty recipe data gracefully (show "add recipe costs to enable forecasting" message).
7. **google_mlkit_text_recognition increases APK size** — ~20MB. Acceptable. If build fails on size, use ProGuard rules.
8. **Do not modify existing Level 1-10 features' behavior** — only add new files + extend routes/settings. Exception: order_page.dart (add upsell widget), voice_ordering_page.dart (upgrade), menu_page.dart (add scan FAB), aggregator_import_page.dart (add scan button), tables_page.dart (add turn badges).
9. **Version bump** — update pubspec.yaml version to 3.1.0+4 (minor bump for AI features).
